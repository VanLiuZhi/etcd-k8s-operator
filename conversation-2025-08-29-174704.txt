     项目架构概览

     etcd-k8s-operator 是一个基于 Kubernetes Operator 模式的控制器，用于管理 etcd 集群的生命周期。项目采用标准的 
     Kubebuilder 项目结构：

     主要组件

     1. API定义 (api/v1alpha1/) - 定义 EtcdCluster CRD 和相关状态
     2. 控制器 (internal/controller/) - 协调 EtcdCluster 资源的主要逻辑
     3. 集群管理 (pkg/cluster/) - etcd 集群的核心管理逻辑
     4. etcd客户端 (pkg/etcd/) - 与 etcd 集群交互的客户端封装
     5. Kubernetes资源管理 (pkg/k8s/) - 管理 Pod、Service、PVC 等 Kubernetes 资源

     核心工作流程

     1. 控制器启动流程

     - cmd/main.go 初始化控制器管理器
     - 创建 EtcdClusterReconciler 并注册到控制器管理器
     - 启动控制器管理器开始监听 EtcdCluster 资源变化

     2. 协调循环 (Reconciliation Loop)

     EtcdClusterReconciler 的主要职责：
     - 监听 EtcdCluster 资源的创建、更新、删除事件
     - 为每个 EtcdCluster 创建对应的 Cluster 实例
     - 通过 Cluster 实例管理 etcd 集群的生命周期

     3. 集群管理核心逻辑

     Cluster 结构体是集群管理的核心：
     - setup() - 集群初始化，根据当前状态决定是创建还是恢复集群
     - run() - 启动协调循环，定期检查并修正集群状态
     - reconcile() - 核心协调逻辑，确保集群状态与期望状态一致

     4. 扩缩容实现机制

     扩缩容通过以下步骤实现：
     1. 状态检测 - 在 reconcile() 中比较当前成员数与期望大小
     2. 成员协调 - reconcileMembers() 处理成员变更
     3. 大小调整 - resize() 根据需要调用 addOneMember() 或 removeOneMember()
     4. 成员添加 - addOneMember() 向 etcd 集群添加新成员并创建对应 Pod
     5. 成员移除 - removeOneMember() 从 etcd 集群和 Kubernetes 中移除成员

     关键数据结构

     EtcdCluster CRD

     - ClusterSpec - 定义集群期望状态（大小、版本、Pod策略等）
     - ClusterStatus - 记录集群当前状态（阶段、条件、成员状态等）

     Member 和 MemberSet

     - Member - 表示 etcd 集群中的一个成员
     - MemberSet - 成员集合，提供成员管理操作（添加、移除、比较等）

     状态管理机制

     通过 ClusterStatus 和条件（Condition）跟踪集群状态：
     - ClusterPhase - 集群阶段（创建中、运行中、失败等）
     - ClusterCondition - 集群条件（可用、恢复中、扩缩容中、升级中等）
     - 状态更新通过 updateCRStatus() 同步到 Kubernetes API Server

     故障处理和恢复

     - 法定人数保护 - 确保集群操作不会导致失去法定人数
     - 错误恢复 - 通过定期协调循环自动恢复集群到期望状态
     - 致命错误处理 - 检测并报告不可恢复的错误状态

     资源管理

     - Pod管理 - 通过 k8s 包创建和删除 etcd Pod
     - Service管理 - 创建客户端和 peer 服务用于集群通信
     - PVC管理 - 支持持久化存储，管理 Pod 对应的持久卷声明

  Go 语言的 init() 函数机制

  1. 自动执行: init() 函数会在程序启动时自动执行，甚至在 main() 函数之前
  2. 执行时机: 包级别的变量初始化 → init() 函数 → main() 函数
  3. 每个包可以有多个: 一个包中可以定义多个 init() 函数，它们会按照出现的顺序执行
